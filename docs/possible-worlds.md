# Possible Worlds / 可能世界叙事

这份文档不是功能清单，而是回答一个更重要的问题：

> 如果“同文异步开放性任务孪生”成为 Codex 的基础原语，它最终可以让长期 Agent 变成什么？

这里的“可能世界”不是宣传口号，而是用具体故事描述这个框架在不同成熟度下可以达成的结果。

---

## 世界 A：一个会把事情真正做完的 Codex

用户让 Codex 修一个上传 Bug。

主线程完成了代码、跑通了测试，然后自然地转去回答下一个问题。它没有意识到：

- README 仍描述旧行为；
- changelog 没更新；
- 工作树里还有调试文件；
- 用户最初还要求“回群报告”，但没有做；
- GitHub issue 仍处于未闭环状态。

普通 Agent 的典型状态是：“核心工作做了，所以任务看起来完成了。”

同文孪生在主线程离开时 fork：

```text
主线程：继续下一个任务

孪生体：
“我们刚才承诺过什么？”
“哪些承诺已经在现实里成立？”
“哪些只是口头上说完成了？”
```

它发现遗漏后，把已经授权、低风险的收尾补完，并把需要主线程确认的事项写信回去。

结果不是“更聪明地写代码”，而是：

> **Codex 从会做任务，变成会闭环任务。**

---

## 世界 B：一个能在你离开以后继续怀疑自己的 Codex

主线程经过 40 分钟 Debug，最后形成判断：

> 根因是 provider 状态没有透传。

实现已经按这个判断修改。

但孪生体保留了同一完整上下文，并没有被“最终答案”强制说服。它在后台重新阅读日志、代码和失败轨迹，发现：

- provider 实际透传正常；
- 真正异常只出现在上传后极短时间窗；
- 主线程把相关性误判成了因果。

它没有静默推翻主线程，而是留下：

```text
[warning / premise]

你刚才的修复依赖前提：
“provider state 没有正确透传”。

我重新检查后发现该前提不成立。

证据：
- file A ...
- log B ...
- test C ...

更符合证据的解释：
上传完成事件早于文件实际可读取，属于 existence race。
```

主线程下一次回到项目时，不需要重新经历整场 Debug，就能看到另一个“自己”留下的证据。

结果是：

> **Agent 第一次拥有了异步自我纠错，而不是只能在当前思路里越走越深。**

---

## 世界 C：一个晚上会“睡觉整理记忆”的 Codex

白天主线程连续完成多个任务。

它不需要每次都停下来总结：

> “现在我要保存记忆。”

每个自然检查点都会产生一个上下文镜像。后台孪生体把共同经历整理为：

```text
原始经历
↓
状态时间线
↓
错误假设与证据
↓
最终根因
↓
可复用经验
↓
原始文件 / commit / 测试指针
```

夜间低负载时，又有一个 consolidation twin 重新观察当天多个记忆：

```text
Episode 31
Episode 42
Episode 57
      ↓
发现三次问题其实属于同一种生命周期竞态
      ↓
形成更高阶项目规律
```

它不删除原始经历，只建立新的上层索引。

第二天主线程碰到类似问题时，知识库直接召回过去的真实轨迹。

结果是：

> **Codex 不再只有“上下文”，而开始拥有“经验”。**

## 世界 D：一个项目拥有自己的守夜人

一个项目已经持续开发数月。

主线程白天做功能，孪生体则像项目守夜人一样长期观察：

- 文档是否逐渐和代码漂移；
- 哪些临时 workaround 已经被当成永久设计；
- 哪些测试长期只测实现细节，没有测用户目标；
- 哪些 TODO 被不断绕过；
- 哪些历史约束后来已经失效；
- 哪些“以后再做”已经被遗忘。

它不是每天机械扫 checklist，而是从完整项目语境里问：

> “如果我是这个项目本身，还有什么正在失去一致性？”

于是项目逐渐形成一种“自我维护能力”。

结果是：

> **AI 不只是参与项目，项目开始拥有一个持续存在的认知代理。**

## 世界 E：一个复杂任务可以同时活出多个未来

主线程正准备采用方案 A。

在传统多 Agent 里，主代理通常写三份 briefing：

- 你评估 A；
- 你评估 B；
- 你做安全审查。

每个子代理都要重新理解世界。

同文孪生则直接从同一个认知状态 fork：

```text
C(t)
├─ Main：执行 A
├─ Twin-1：假设采用 B，继续推演
├─ Twin-2：站在未来维护者视角观察
└─ Twin-3：专门尝试推翻当前前提
```

几条分支不是“几个员工”，而是同一个认知体的几个未来版本。

之后主线程可以只合并其中有证据价值的发现：

```text
fork
→ explore
→ test
→ compare evidence
→ merge
```

结果是：

> **AI 获得一种人类天然缺失的能力：并行活过多个认知未来，再把结果带回来。**

## 世界 F：一个不会因为“换班”失去现实理解的后台团队

主线程已经积累了大量隐含语境：

- 用户为什么否掉方案 B；
- 哪个约束来自一次失败；
- 哪个看似奇怪的设计其实有历史原因；
- 当前哪些判断只是暂定；
- 哪些东西已经被真实环境验证。

如果把任务交给普通子代理，就必须先把这些压成 briefing。

而孪生体直接继承：

```text
同一个过去
+
不同的未来任务
```

所以复杂工作不需要为了“分工”先牺牲现实理解。

结果是：

> **Harness 可以把“完整理解现实”本身当成可复制资产。**

这会改变 Agent 调度逻辑：

```text
可描述、低上下文依赖任务
→ 普通子代理

高度依赖认知现场的任务
→ 同文孪生
```

## 世界 G：知识库不再是人工维护的附件

给孪生体接一个向量知识库工具以后，它可以把后台工作自然写入长期项目记忆：

- state vector：当时世界是什么状态；
- delta vector：发生了什么变化；
- trajectory vector：认知和任务怎样演化；
- evidence pointer：原始代码、日志、录像、commit 在哪里；
- semantic note：需要给人看的解释。

主线程不负责“整理知识库”。

主线程只工作。

孪生体像后台档案员一样，把工作留下的认知痕迹变成未来可搜索的经验。

结果是：

> **知识库从“需要人提醒 AI 去维护的工具”，变成 Agent 生命周期的自然副产品。**

---

## 世界 H：一个长期 Codex 可以从“工具”进化成“项目人格”

当主线程、同文孪生、长期知识库和项目状态长期联动以后，用户不再只是“每次打开一个新的 Coding Agent”。

项目本身可以拥有连续性：

> “为什么三个月前没有采用这个方案？”

项目 Agent 可以回答，并给出当时的证据。

> “最近哪些地方越来越脆弱？”

守夜孪生可以指出长期积累的漂移。

> “这个 Bug 我们以前是不是碰到过？”

知识库可以召回当时完整认知轨迹。

结果是：

> **同一个模型开始表现得像“在这个项目里生活过很久的人”。**

这不是通过无限增大一次性上下文实现，而是通过：

```text
当前工作上下文
+
同文认知分叉
+
异步巩固
+
长期可检索记忆
```

共同形成。

## 世界 I：主线程很快，后台很深

今天常见的两难是：

- 前台 reasoning 很深 → 用户等待很久；
- 前台 reasoning 很浅 → 复杂任务容易漏东西。

同文异步孪生允许把两者拆开：

```text
前台主线程
→ 快速推进现实任务

后台孪生
→ 花更长时间复盘、验证、查资料、检查副作用
```

用户可以先得到进展，而不是等待所有二阶思考完成。

如果后台发现严重问题，再通过 mailbox 回来。

结果是：

> **前台延迟与后台智能第一次可以解耦。**

---

## 世界 J：从“多 Agent 组织”走向“可分叉认知”

这个框架最远的意义并不是增加一种子代理类型，而是改变对数字智能的基本假设。

人类天然只有一条连续人生，因此习惯把 AI 设计成：

```text
一个 Agent
→ 一条认知时间线
```

但数字智能可以：

```text
snapshot
→ fork
→ parallel futures
→ evidence merge
→ consolidate
→ fork again
```

于是未来 Harness 的基本原语可能不再只是：

- delegate；
- call tool；
- summarize；

而会增加：

- fork cognition；
- freeze；
- replay；
- branch；
- compare；
- merge；
- consolidate。

结果是：

> **AI 不再只是“一个更快的人”，而开始使用人类根本没有的认知原语。**

## 成熟度阶梯

```text
L1  同文复盘
    主线程结束阶段任务后，主动 fork 一个完整上下文孪生做复盘。

L2  异步闭环
    孪生不阻塞主线程，能自行补低风险遗漏并异步回信。

L3  长期记忆
    孪生接知识库/向量库，负责状态化、索引、证据绑定和巩固。

L4  多未来认知
    同一快照 fork 多个认知未来，进行反事实、验证、维护者视角和攻击者视角推演。

L5  原生认知运行时
    runtime 直接支持 snapshot / fork / shared-prefix cache / merge / mailbox，
    同文孪生成为 Agent 的基础认知原语。
```

当前仓库首先瞄准 **L1 → L2**。

L3 是最自然的下一阶段。

L4/L5 则是这个架构的长期上限。

## 一句话愿景

> **不要让一个已经理解现实的 Agent，为了做第二件复杂事情先失忆再交接。复制它，让另一个自己继续活下去。**
