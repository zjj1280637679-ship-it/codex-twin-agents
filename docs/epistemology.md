# Epistemology / 认识论

这份文档描述 **同文异步开放性任务孪生** 背后的认知模型。

核心问题不是“要不要继承上下文”，而是：

> **哪些认知成分应该连续，哪些应该在分叉后获得重新推导的自由。**

---

## 1. 四元组：目标—条件—策略—指标

把一个工作中的 Agent 状态抽象为：

```text
(G, C, S, M)
```

其中：

- **G / Goal / 目标**：抽象主观。用户真正想达成什么，为什么做这件事。
- **C / Conditions / 条件**：具象客观。当前 Agent 认为现实是什么样：代码、文件、日志、系统状态、证据、约束、工具结果。
- **S / Strategy / 策略**：抽象客观。在当前目标和条件下，应该采用什么路线。
- **M / Metrics / 指标**：具象主观。用什么可观察信号判断策略是否有效、任务是否完成。

可以写成：

```text
目标 G
  + 条件 C
      ↓
   策略 S
      ↓
   指标 M
```

关键点：**S 和 M 不是现实本身。**

它们是基于当前现实模型和目标形成的工作性产物。

因此：

> 策略可以失效，指标也可以失效，而目标和现实仍然成立。

---

## 2. 主线程为什么天然“小步快跑”

主线程处于连续行动压力中：

- 已经开始实现；
- 已经做出承诺；
- 用户正在等待；
- 当前方案已有投入；
- 测试框架已经搭起来；
- 下一步通常只差一点点；
- 每次大更新都会产生新的重规划成本。

所以主线程倾向于：

```text
C 有一点变化
↓
对 S 打补丁
↓
继续沿 M 前进
```

而不是：

```text
C 变化
↓
重新规划整个 S
↓
重新定义 M
```

这不是简单缺陷。

**稳定执行本身就是生产系统需要的能力。**

如果一个 Agent 每收到一点新证据就重新定义现实、策略和成功标准，它可能永远无法完成任务。

因此：

> 主线程的职责不是“永远最开放”，而是“在当前现实模型下稳定推进”。

---

## 3. 两种不同的锁

长期工作会形成两种互相独立的惯性。

### 3.1 认知锁：Conditions Lock

Agent 可能已经把某种世界解释当成默认现实。

例如：

> “问题发生在 provider 透传层。”

后来它所有注意力、测试、搜索和修复都围绕这个条件模型展开。

即使 fork 一个完整同文孪生，孪生体仍继承：

- 相同的证据选择历史；
- 相同的分类方式；
- 相同的被否路线；
- 相同的注意力分配；
- 相同的因果叙事。

因此同文孪生可以摆脱行动执念，却仍可能受 **见知障** 约束。

它可能做到：

```text
(G, C, S, M)
→
(G, C, S', M')
```

却没有做到：

```text
C → C'
```

也就是：

> **摆脱了“怎么做”的执念，却没有摆脱“世界就是这样”的执念。**

---

### 3.2 行动锁：Strategy / Metric Lock

反过来，即使 Agent 获得了新的现实条件：

```text
C → C'
```

它也未必会大幅更新策略和指标。

因为主线程仍承受：

- 进度压力；
- 已投入成本；
- 当前承诺；
- 连续叙事；
- 局部 KPI；
- “快做完了”的完成压力。

所以可能出现：

```text
C'
↓
旧 S + 小修补
↓
旧 M
```

也就是：

> **看见了新现实，却仍然沿着旧任务结构跑。**

---

## 4. 课题分离：知识继承 ≠ 指标继承

因此，“上下文继承”不是一个单一布尔值。

更准确地说，应至少区分：

```text
知识 / 条件是否继承？
策略 / 指标是否继承？
```

对开放孪生来说，理想状态不是“把一切照搬”。

而是：

```text
保留：
G 根目标
C 现实条件
证据历史
用户约束

重推：
S 策略
M 指标
```

形式化地：

```text
(G, C, S, M)
→
(G, C, S', M')
```

一句话：

> **目标和现实连续，路线和考核方式重新出生。**

这就是同文开放孪生的第一性定义。

---

## 5. 目的重启：Teleological Reboot

主线程工作越久，越容易发生：

```text
策略 → 被误当成目标
指标 → 被误当成现实
```

例如：

用户真正目标：

> 上传后 AI 能稳定读取源文件。

中途策略：

> 修改 provider 透传逻辑。

阶段指标：

> 测试返回 200 / 单测通过。

主线程在压力下很容易逐渐变成：

> “只要这个测试绿了，我们就完成了。”

开放孪生应该把这些层级重新展开：

```text
G：用户真正要什么？
C：现实到底发生了什么？
S：当前路线仍然是最合理的吗？
M：我们现在用的成功标准真的证明了 G 吗？
```

所以开放孪生不是失忆，而是：

> **继承认识，不继承执念。**

也可以叫：

> **Teleological Reboot / 目的重启**

即：

```text
inherit epistemic state = high
inherit root intent = high
inherit local strategy = low
inherit local metric = low
```

## 6. 认知自由度 × 行动自由度

从更深层看，可以建立另一个二维坐标系。

横轴：

> **Epistemic Freedom / 认知自由度**  
> 是否允许重新构建条件 C

纵轴：

> **Teleological Freedom / 目的-行动自由度**  
> 是否允许重新构建策略 S 与指标 M

得到四种认知模式：

| | S/M 连续 | S/M 可重启 |
|---|---|---|
| **C 连续** | ① 主线程连续执行 | ② 同文开放孪生 |
| **C 可重构** | ③ 现实校准器 | ④ 全重构孪生 |

### ① 主线程连续执行

```text
C 锁定
S/M 锁定
```

优势：高稳定、高吞吐、能完成任务。  
风险：路径依赖、局部最优。

### ② 同文开放孪生

```text
C 连续
S/M 重启
```

优势：保留完整现实理解，同时重新推策略和指标。  
风险：仍然继承主线程的见知障。

它回答：

> **“如果世界还是我们理解的这个世界，是否应该换一种活法？”**

### ③ 现实校准器

```text
C 重构
S/M 暂不处理
```

任务不是重新规划，而是重新查清：

> “我们对现实条件的理解是真的吗？”

它可以独立检查：

- 实际文件生命周期；
- API 真实语义；
- 官方文档；
- 日志与时间顺序；
- 真实调用路径；
- 环境差异；
- 被主线程忽略的外部证据。

它回答：

> **“我们是不是从一开始就看错了世界？”**

### ④ 全重构孪生

```text
G 保留
C 重构
S 重推
M 重推
```

即：

```text
(G, C, S, M)
→
(G, C', S', M')
```

这是最激进的模式。

最好保留：

- 根目标；
- 原始用户表达；
- 原始证据；
- 文件、日志、commit、tool result；
- 权限与硬约束。

但把：

- 旧结论；
- 旧分类；
- 旧因果解释；
- 旧策略；
- 旧 KPI；

全部降级成历史候选，而不是默认真理。

这可以叫：

> **Clean-room Re-foundation / 净室式重新奠基**

---

## 7. 为什么②和③必须互补

②解决：

> “是不是我们的做法错了？”

③解决：

> “是不是我们看到的世界错了？”

这两个问题正交。

因此一个强 Harness 不应该只拥有同文开放孪生，还应该保留独立现实校准能力。

理想流程：

```text
                 Root Goal G
                     │
        ┌────────────┴────────────┐
        ↓                         ↓
② 同文开放孪生               ③ 现实校准器
保持 C                       重建 C
重推 S/M                     暂不碰 S/M
        │                         │
        └────────────┬────────────┘
                     ↓
                检测认知冲突
                     ↓
                ④ 全重构孪生
               C' → S' → M'
```

所以系统需要两种逃逸机制：

> **从行动惯性中逃逸。**

以及：

> **从认知惯性中逃逸。**

只有两者都存在，才有机会跨出更深的局部最优。

## 8. 与“上下文继承 × 任务开放度”坐标系的关系

仓库已有的组织层坐标系是：

| | 指向型分工 | 开放性辅助 |
|---|---|---|
| **上下文不继承** | Delegate | Observer |
| **上下文继承** | Forked Worker | Cognitive Twin |

这个坐标系描述：

> **代理如何被组织。**

本文件的：

```text
条件 C 是否可重构
×
策略/指标 S/M 是否可重构
```

描述：

> **代理拥有多少认知自由。**

两者不是重复关系。

一个“全上下文继承代理”仍然可能被要求保持原策略，因此认知自由度很低。

一个“上下文不继承的观察者”反而可能拥有很高的条件重构自由度。

因此：

> **组织拓扑 ≠ 认知自由度。**

未来 Harness 应同时建模两者。

## 9. 分身句柄应该表达什么

完整上下文 fork 后，最小分身句柄不应该重新写一份 briefing。

它更应该声明：

```text
你是谁？
哪些东西连续？
哪些东西解除绑定？
你与主线程是什么关系？
结果往哪里回？
```

例如开放孪生：

```text
fork_mode: OPEN_TWIN

inherit:
  root_goal: true
  world_conditions: true
  evidence_history: true
  user_constraints: true

reset:
  local_strategy: true
  local_metrics: true
  completion_pressure: true

recompute:
  strategy_from_first_principles: true
  metrics_from_root_goal: true

return:
  channel: parent_mailbox
```

这不是重新描述任务。

这是一个：

> **认知继承矩阵。**

## 10. 更一般的认知分叉代数

四元组让 fork 不再只是“复制整个 Agent”。

它可以指定不同维度的连续与重置：

```text
保留 G,C；重推 S,M
→ 开放孪生

保留 G,C,S；重推 M
→ 独立验收孪生

保留 G,C,M；重推 S
→ 替代方案孪生

保留 G；重构 C,S,M
→ 净室重新奠基

保留 C；重推 G,S,M
→ 问题重定义 / 外部审视
```

因此未来真正的 fork 原语可能不是：

```text
clone_agent()
```

而更接近：

```text
fork(
  inherit = {...},
  reset = {...},
  recompute = {...},
  divergence_intent = ...
)
```

这可以看作一种 **认知分叉代数（Cognitive Fork Algebra）**。

## 11. 核心原则

可以把本项目的认识论压缩成六句话：

1. **目标、条件、策略、指标不是同一个层级。**
2. **策略不是目标，指标也不是现实。**
3. **更新条件，不等于会更新策略和指标。**
4. **更新策略和指标，也不等于能更新条件。**
5. **主线程需要稳定执行，开放孪生负责摆脱行动惯性，现实校准器负责摆脱认知惯性。**
6. **连续的现实认识，不应该强迫连续的目的论结构。**

最短版本：

> **同文分身解决“知道同样的世界，能不能换一种活法”；异文观察解决“我们是不是从一开始就活在错误的世界模型里”。**

## 12. 权限拓扑不等于信息拓扑

这个项目进一步把“父子代理”拆成两个彼此独立的问题：

    Authority / 权限：谁能创建、停止、批准、重定向谁
    Information / 信息：谁拥有多少上下文、记忆、证据与项目历史

因此：

> **父子关系是治理关系，不是知识论关系。**

一个子代理可以权限更低，但信息与父代理等效；也可以在父上下文之外继续加载长期记忆、额外检索或另一个项目，从而形成信息超集。

也就是说：

    A_child < A_parent
    I_child = I_parent

或者：

    A_child < A_parent
    I_child > I_parent

两者并不矛盾。

传统“子代理”概念常把“子”误解成“信息子集”。这是一种实现惯性，而不是 AI 上下文的本质。

## 13. 上下文拓扑

上下文关系不应只有“继承 / 不继承”两档。更一般地可以有：

    MINIMAL     只给任务所需的最小上下文
    PARTIAL     继承最近或选定上下文
    EQUIVALENT  拥有与主代理等效的完整上下文
    SUPERSET    完整继承后，再增加额外知识与记忆
    FUSED       融合多个项目、多个历史或多个认知来源

Codex Twin Agents 当前只实现其中一个非常小但重要的入口：EQUIVALENT / 同文分叉。

这个入口的意义不在于“子代理变得更高级”，而在于提醒系统：

> **不要因为一个执行分支叫子代理，就默认它必须比父代理知道得少。**

进一步的 SUPERSET 和 FUSED 说明，未来子代理甚至可以拥有比主代理更长、更广的上下文。

例如：

    Project A context -----\
                           > Fusion Agent
    Project B context -----/

这里的关键是保留来源身份、时间、项目边界和冲突关系；融合的是认知来源，而不是把文本简单搅在一起。

## 14. 从 Multi-Agent 到 Context Topology Runtime

如果把 Agent 当成第一性对象，就很容易被“主代理 / 子代理 / 专家代理”的人类组织隐喻限制。

更底层的对象其实是：

    context_state
    +
    execution_branch

数字上下文天然可以被：

    copy
    crop
    expand
    fuse
    fork
    rollback
    replay
    compare
    merge

因此未来更一般的问题不是：

> “我要再创建什么子代理？”

而是：

> **“我要如何变换、组合并运行这份上下文？”**

这可以称为 Context Topology Runtime / 上下文拓扑运行时。

## 15. 穿越认知障

很多看起来像“模型能力不足”的现象，其实来自 Harness 对自由度的提前收窄：

    父 = 权限高 = 信息多
    子 = 权限低 = 信息少
    分工 = briefing
    并行 = 压缩上下文
    子代理 = 局部执行
    继承上下文 = 继承策略和指标

这些等式都不是 AI 上下文的自然定律。

本项目的理论立意因此可以压缩为：

> **穿越认知障，让代理回归它本来就可以拥有的上下文自由。**

工程上则是：

> **解耦权限、信息、任务、目标、策略和指标，让每个维度按任务本身，而不是按“子代理”这个标签决定。**

所以目标不是先给模型增加新的智能能力，而是先解除那些不必要的默认绑定。

> **不是增强智能，而是解除认知约束。**
